‏R, RE ו־coRE

מודלים חישוביים — פרק 11 (הרצאה 11 + תרגול 11)

שלוש המחלקות במבט אחד

  • R — קיים מכריע: עוצר תמיד ועונה נכון.
  • RE — קיים מזהה: מקבל בדיוק את מילות השפה (על השאר — דוחה או מתלולאת).
  • coRE — המשלים ניתן לזיהוי: ‏L ∈ coRE ⟺ L ∈ RE.

אינטואיציית העדים: שפה ב-RE אם ל"כן" יש עד סופי שאפשר למצוא (ריצה מקבלת, מילה, זוג…); ב-coRE אם ל"לא" יש עד כזה. ‏R = שני הצדדים מאושרים בזמן סופי.

כל השפות
RE ∪ coRE
R = RE ∩ coRE

ארבעה אזורים למפה: ‏R; ‏RE ∖ R (עד ל"כן" בלבד — ‏ATM); ‏coRE ∖ R (עד ל"לא" בלבד — ‏ATM, ‏ETM); ומחוץ לשניהם (‏REGTM, ‏EQTM).

R = RE ∩ coRE

‏L ∈ R אם ורק אם L ∈ RE וגם L ∈ coRE.
⇐ מכריע ל-L הוא מזהה ל-L; והיפוך תשובתו — מכריע (ובפרט מזהה) ל-L (מותר להפוך תשובות של מכריע — הוא תמיד עוצר!).
⇒ יהיו M₁ מזהה ל-L ו-M₂ מזהה ל-L. המכריע מריץ את שניהם במקביל (צעד לזה, צעד לזה — או על שני סרטים): כל מילה שייכת לאחת השפות, ולכן אחת הריצות תעצור-ותקבל בזמן סופי; אם M₁ קיבלה — קבל, אם M₂ — דחה. ∎
שתי נקודות שנבחנות שוב ושוב: (1) להפוך תשובות של מזהה אסור — לולאה נשארת לולאה, לא הופכת לקבלה; היפוך כשר רק למכריע. (2) הריצה במקביל חיונית — "קודם M₁ עד הסוף ואז M₂" נתקעת אם M₁ מתלולאת.

A_TM ∈ RE — המכונה האוניברסלית

ATM = {⟨M, w⟩ | M is a TM and M accepts w}

המזהה

U': "On input ⟨M, w⟩:
1. Simulate M on w (using the universal machine).
2. If M accepted — accept. If M rejected — reject."

אם M מקבלת את w — הסימולציה מגלה זאת בזמן סופי ⇒ קבלה. אם לא — דחייה או לולאה (הסימולציה נמשכת לנצח). זה בדיוק פרופיל של מזהה: ‏ATM ∈ RE.

‏ATM היא "אמא של RE" — עוד לפני שנדבר על שלמות: כל שאלת "האם M מקבלת" מגולמת בה. השאלה הגדולה: האם אפשר להכריע אותה?

שיטת האלכסון: A_TM ∉ R

נניח בשלילה שקיים מכריע H ל-ATM: ‏H(⟨M,w⟩) עונה "כן" אם M מקבלת את w, "לא" אחרת — ותמיד עוצר. נבנה את המכונה: 
D: "On input ⟨M⟩:
1. Run H on ⟨M, ⟨M⟩⟩.
2. If H says yes — reject; if H says no — accept."
‏D מכונה חוקית (משתמשת ב-H העוצר), אז נריץ אותה על הקידוד של עצמה: ‏D(⟨D⟩) מקבלת ⟺ ‏H ענה "לא" על ⟨D,⟨D⟩⟩ ⟺ ‏D לא מקבלת את ⟨D⟩ — סתירה. לכן H לא קיים. ∎

זהו לב הקורס: ההפניה העצמית (מכונה שרצה על הקוד של עצמה) הופכת מכריע-לכאורה למכונה סותרת-עצמה. אותו רעיון כמו הפרדוקס של השקרן ("המשפט הזה שקרי") — אבל ממוסד למתמטיקה.

מסקנה מיידית: ‏RE ≠ R — ההכלה ממש. ובצירוף R = RE ∩ coRE: ‏ATM ∉ coRE (אחרת הייתה ב-R). את המסקנה הזו נארוז בנושא הבא.

המשלים והמפה: A_TM ∉ coRE

ATM ∈ RE ∖ R, ולכן: ‏ATM ∉ coRE, ‏ATM ∈ coRE ∖ R, ‏ATM ∉ RE.

כללי המשלים ששווה לשנן (סימטריה מושלמת):

  • L ∈ R ⟺ L ∈ R (מכריע מתהפך).
  • L ∈ RE ⟺ L ∈ coRE (הגדרה).
  • L ∈ RE ∖ R ⟹ L ∈ coRE ∖ RE… ליתר דיוק: ‏L ∈ coRE ∖ R, וגם L ∉ RE (אחרת שתיהן ב-RE ⇒ שתיהן ב-R).

סימולציה מוגבלת־צעדים — הכלי

הבעיה: "הרץ את M על x" עלול לא לעצור. הפתרון: "הרץ את M על x למשך i צעדים" — צעד שתמיד עוצר, ומדווח אחת משלוש: קיבלה / דחתה / לא סיימה עדיין.

הבנייה המבריקה של 2024ב ש2

N_{M,w}: "On input x:
1. Run M on w for |x| steps.
2. If M didn't accept during these steps — accept.
3. Otherwise — reject."

אם M לא מקבלת את w — ‏N מקבל כל קלט. אם מקבלת תוך k צעדים — ‏N מקבל בדיוק את המילים הקצרות מ-k (שפה סופית ≠ ‏Σ*). כך התכונה "מקבלת-כל-קלט" של N מקודדת את "M לא מקבלת את w" — רדוקציה מ-ATM! (מלוא הפרטים בפרק 12.)

הטריק "אורך הקלט כתקציב צעדים" הופך שאלת-אינסוף (האם אי-פעם?) לסדרת שאלות סופיות. שווה לזהות אותו מיד — הוא מופיע כמעט בכל בניית מכונה מתוחכמת במבחנים.

Dovetailing — לולאת החיפוש האינסופית

איך מזהה מחפש עד (x, k) — מילה ותקציב — כששניהם לא חסומים? מסדרים את כל הזוגות בסדרה אחת ובודקים בזה אחר זה:

התבנית (כמו במזהי 2023–2024)

M_L: "On input ⟨M⟩:
1. For i from 0 to ∞:
   1.1. For every x with |x| ≤ i, in lexicographic order:
      1.1.1. Run M on x for i steps.
      1.1.2. If M accepted — accept."

כל איטרציה i — עבודה סופית (מספר סופי של מילים, כל אחת ל-i צעדים). אם קיים עד — נגיע לאיטרציה שבה גם המילה נכללת וגם התקציב מספיק, ונקבל. אם לא — נרוץ לנצח, וזה בסדר: אנחנו מזהה, לא מכריע.

הטעות הפוסלת: "לכל x: הרץ את M על x עד הסוף" — ריצה אחת מתלולאת חוסמת את כל הבאות אחריה. התקציב i (או ריצה-במקביל) הוא לא קישוט — הוא מה שמציל את הזיהוי. בהוכחת הנכונות חובה גם לנמק שכל איטרציה סופית — כמו שהפתרונות הרשמיים עושים במפורש.

תבנית ה־∃: מתי שפה ב־RE

שפה מהצורה {⟨M⟩ | ∃ עד סופי שניתן לאימות בזמן סופי} — ב-RE. המזהה: ‏dovetailing על כל העדים האפשריים + אימות כל מועמד.
  • "‏∃x: M מקבלת את x" (‏ETM) — עד: זוג (מילה, תקציב) ✓ RE.
  • "‏M עוצרת על w" (‏HALTTM) — עד: מספר הצעדים ✓ RE.
  • "‏∃x, y: ‏M עוצרת על x ודוחה את y ו-xy ∈ L(D)" — שאלה 2 של 2024א, עד מורכב (שני זוגות) — אותה תבנית, לולאה מקוננת יותר ✓ RE.
מבחן מהיר: נסחו את תנאי השפה ככמת. אם הוא "∃ + אימות סופי" — יש מזהה. שימו לב שהאימות חייב לעצור: "‏M דוחה את y" ניתן לאימות (מחכים לדחייה); "‏M לא מקבלת את y" — לא (אולי לולאה)!

תבנית ה־∀: מתי שפה ב־coRE

שפה שהמשלים שלה מנוסח כ-∃ (כלומר: השפה עצמה היא תנאי ∀) — ב-coRE. המזהה-של-המשלים מחפש עד-נגדי.
  • ‏ETM = {⟨M⟩ | ∀x: M לא מקבלת} — המשלים "∃ מילה מתקבלת" ב-RE ⇒ ‏ETM ∈ coRE.
  • "‏∀w ∈ PAL: M לא דוחה את w·w" (שאלה 2 של מבחן-לדוגמה) — עד-נגדי: פלינדרום שנדחה ✓ coRE.
  • ‏L(M) ⊆ L(D)∘L(D) (‏2023א ש2) — עד-נגדי: ‏w ∈ L(M) שאינו בשרשור ✓ coRE.
כמת מעורב — ‏∀∃ או ∃∀ שלא מצטמצם — רמז חזק לאזור "מחוץ לשניהם": ‏REGTM ("‏∃ אוטומט כך ש-∀ מילה…"), ‏EQTM. שם לא עוזר שום מזהה — ומוכיחים עם שתי רדוקציות (פרק 12).

אסטרטגיית שאלה 2 במבחן

שאלה 2 (40 נק'!) היא תמיד: שפה של קידודים, ושלוש שאלות — ‏L ∈ R? ‏L ∈ RE? ‏L ∈ coRE? עם הוכחה מלאה. סדר עבודה:

  1. כתבו את תנאי השפה בכמתים, ואת המשלים (היפוך הכמתים!) — חצי מהפתרון נמצא כאן.
  2. ‏∃+אימות-עוצר ⇒ כנראה RE (בנו מזהה dovetailing); ‏∀ ⇒ כנראה coRE (מזהה למשלים); מעורב ⇒ כנראה אף אחד.
  3. כתבו את המזהה במלואו + נכונות דו-כיוונית ("אם בשפה — יגיע לקבלה כי…; אם לא — לא יקבל לעולם כי…").
  4. לצד השלילי — רדוקציה מ-ATM או ATM (פרק 12). זכרו: ‏∉ coRE ⟹ ∉ R, ‏∉ RE ⟹ ∉ R — תשובת ה-R מגיעה בחינם מאחת השלילות.

הדפוס בשלושת המבחנים האחרונים

‏2024א: ‏RE כן, coRE לא (⇒ R לא). ‏2024ב: הכול לא — שתי רדוקציות (‏ATM וגם ATM). ‏2023א: ‏coRE כן, RE לא. שלושת הפרופילים האפשריים — והמנגנון זהה: מזהה לצד החיובי, רדוקציה לצד השלילי.

לב הפרק: ‏R = שני עדים, RE = עד ל"כן", coRE = עד ל"לא"; האלכסון קובע ‏ATM ∈ RE∖R; סימולציה מוגבלת + dovetailing הם המנוע של כל מזהה; והכמתים של תנאי השפה הם המצפן של שאלה 2.
